# Вокал - тренажёр и игры для пения

Личный проект Кита (nchurashov). Тренажёр вокала + игры, где голосом управляешь шариком.
Живёт по ссылке https://nchurashov.github.io/vocal/ (GitHub Pages из ветки main, корень) и как iPhone-приложение (ios/, Capacitor).

## Как работать с Китом
- Отвечать по-русски, тепло и коротко. Без длинных тире (—), только дефис (-). Без канцелярита.
- Сначала сделай и проверь сам, потом отчитывайся. Вопрос - только если ошибка дорого стоит.
- Ничего не выдумывать: результаты пользователя только те, что он отметил или что измерил микрофон.
- Перед выкладкой ВСЕГДА гонять тесты (ниже). Особенно честность игры: проверять на имитации живого голоса, а не на демо-автопилоте.

## Структура
- `src/analysis.js` - распознавание высоты тона (YIN), разбиение на ноты, сравнение с эталоном (`evaluate`), живой тон с микрофона (`livePitch`), ритм (`evaluateTaps`). Работает и в Node (тесты).
- `src/data.js` - упражнения (слух/интонация/ритм, уровни 1-3), мелодии для оценки, базовые ноты.
- `src/app.js` - каркас: звук (Web Audio), хранилище, уровни и повторения, экраны (Сегодня, Упражнения, Оценка, История, Заметки, Настройки), запись голоса.
- `src/game.js` - игра «Попади в ноту» (ноты-полосы), маршруты `#game`, `#game-N`.
- `src/learn.js` - клавиатура пианино `pianoSVG` (подсветка диапазона, текущая нота, клавиши со звуком) и страница «Как устроены ноты» (`#learn`): 7 нот C-B = До-Си, полутоны и центы, номера октав, примерные диапазоны голосов. Клавиатура также на замере и в карточке «Где работаем».
- `src/range.js` - замер диапазона (`#range`): засчитываются только ноты, удержанные 0.8 с с разбросом до полутона (`rangeStep`); после замера выбор: середина / нижний / верхний регистр (`rangeChoices`, считается по грудному голосу). Переход в фальцет: кнопка «Перешёл в фальцет» во время замера или нажатие на клавишу после (`chestHi` в записи замера; на клавиатуре грудной и фальцет разными цветами).
- `src/warmup.js` - распевка дня (`#warmup`): дыхание, трель, мычание, сирена, ми-мэ-ма, спуск вниз. Шаг «Переход в фальцет» (фраза 1-3-5-8, верх проходит через `chestHi`) - только если переход отмечен. Режимы: «Повтори за мной» (пианино играет фразу, потом тишина; микрофон слушает только в тишине, `wuScore` - какие ноты чисто, ±50 ц от 0.15 с) и «Вместе с пианино» (без проверки). Тональности (`warmupKeys`) в пределах замера; спуск при замере всегда доходит до низа, затем одна тональность на полутон ниже - если там чисто удержана новая нота (правило `rangeStep`), предлагаем записать новый низ. Проходы в `state.warmups`, дни подряд - `warmupStreak`.
- `src/voice.js` - раздел «Голос и речь» (`#voice`, `#voice-<id>`): 7 комплексов актёрских и логопедических упражнений (снять зажимы, дыхание и опора, резонанс, дикция со скороговорками, плавная речь, низкий голос, шире диапазон). Шаги: таймер, метроном со слогами, скороговорки/фразы, пианино (через `warmupKeys`), замеры «длинный звук на «а»» (по высоте тона) и «выдох на «с»» (шум выше фона) - секундомер `phonStep`, паузы до 0.6 с не обрывают. «Комплекс дня» - следующий по кругу после последнего сделанного. Данные в `state.voice` (done, rec). Кит сам избавился от заикания такими занятиями - плавная речь важна.
- `src/ball.js` - игра «Шарик» (стены с окнами), маршруты `#ball`, `#ball-N`. Вкладка «Игра» ведёт сюда.
- `src/app.css` - стили.
- `build.py` - склеивает src/* в один `index.html` (корень = сайт) и `www/index.html` (для iOS).
- `ios/` - Xcode-проект (Capacitor 8, Swift Package Manager, без CocoaPods). Bundle id `ru.nchurashov.vocal`.
- `tests/` - тесты (см. ниже).

## Сборка и выкладка
```
python3 build.py                 # src -> index.html + www/
npx cap sync ios                 # www -> ios/App/App/public (нужен npm i)
git add -A && git commit && git push   # сайт обновится через ~1 мин
```
iPhone: на Маке открыть `ios/App/App.xcodeproj`, Signing -> Team (Apple ID), выбрать iPhone, ▶.
Бесплатный Apple ID - приложение живёт 7 дней. Аккаунт разработчика ($99/год) - TestFlight.

## Тесты (гонять перед каждым пушем)
```
node tests/test_analysis.js      # распознавание нот
node tests/synth.js              # создаёт tests/out/sing.wav для теста интерфейса
python3 tests/smoke_ui.py        # упражнения, запись с фейкового микрофона, история
python3 tests/sim_ball.py        # честность «Шарика» на всех 12 уровнях
python3 tests/sim_game.py        # честность «Попади в ноту» на всех 12 уровнях (шаг игры - gameStep)
python3 tests/sim_range.py       # замер диапазона: писк, хрип и скольжение не считаются; клавиатура и имена нот
python3 tests/sim_warmup.py      # распевка в границах диапазона, полный проход сохраняется
python3 tests/sim_voice.py       # «Голос и речь»: секундомер замеров, все 7 комплексов проходятся
```
Нужны playwright (python) и Chrome; путь к Chrome через env `CHROME` (по умолчанию /usr/bin/google-chrome).

## Важные решения (не ломать)
- **Октава голоса**: `octLock` в app.js. Октава определяется по первым ~8 кадрам пения и фиксируется на весь уровень. Кадры берутся только внутри тоннеля/ноты: до этого микрофон слышит подсказку пианино из динамика и иначе запирал бы октаву пианино (женский голос октавой выше разбивался). Тест: «октавой выше, динамик слышен» в sim_ball.py. Мужской/женский голос подходят, но нижнее До не засчитывается за верхнее.
- **Где работаем**: базовая нота от C2 до E5 по полутону (`setBase`, карточка `registerCard` на экранах игр и в настройках). Галочка «Только в этой октаве» (`settings.strict`): `octLock` и `evaluate` не сдвигают октаву, для работы над нижним/верхним регистром. Замеры диапазона в `state.range`.
- **Голос**: при первом заходе в игру спрашиваем «низкий / высокий» (`setVoice`, база C3 или C4, `settings.voiceSet`). Кто уже менял ноту в настройках, того не спрашиваем.
- **Точность попадания** (ширина окна) в «Шарике»: ползунок 1-50 центов (`state.settings.tol`, по умолчанию 40), пресеты 40/20/10. Рекорд хранит `tol`; уже = ценнее (`rank`).
- **Засчёт стены**: центр шарика в окне больше половины времени тоннеля, первые 0.22 с (или 30% тоннеля) не считаются, вылет >0.35 с подряд = удар. 3 жизни.
- **Мелодии**: если ноты идут подряд, тоннель начинается позже начала ноты (окно 0.4 с на смену ноты).
- **Уровни тренажёра**: следующий открывается после 3 отметок «Уверенно» за 2 разных дня. Уровень пользователя не предполагать.
- **Повторения**: «не вышло» через 1 день, «частично» через 2, «уверенно» 1-2-4-7-14-30 дней.
- **Звук на iPhone (Safari)**: `navigator.audioSession.type='playback'` ставится только когда звукового движка нет; после микрофона `afterMic()` закрывает движок. Менять режим на ходу нельзя - глушит звук. Микрофон включается только через `openMic()`: закрыть движок -> режим 'play-and-record' -> новый движок -> getUserMedia; пока `micOn`, сторожа (resumeWatch, уход в фон) движок не трогают. При уходе в фон движок закрывается (баг iOS 26 у иконок на экране Домой). В iOS-приложении всё это отключено (`window.Capacitor`), режим звука задаёт AppDelegate.swift.
- **Тишина с микрофона**: с AirPods/Bluetooth микрофон переключает частоту, и движок со старой частотой получает от Safari ровный ноль. `openMic` сверяет частоту трека и пересоздаёт движок; замеры без пианино (диапазон, длинный звук, выдох) читают микрофон через `micTap`: 1.5 с ровного нуля -> один раз пересоздать движок, дальше честная подсказка `MIC_DEAD`. Там же полоска громкости микрофона. Время в этих замерах - `performance.now()`, не часы движка (движок может пересоздаться).
- **Микрофон** внутри Claude (артефакт) закрыт - там запись через камеру телефона (`capture`). На сайте и в приложении - живой микрофон (`MIC_DIRECT`).
- Хранилище: localStorage (сайт, приложение) или db артефакта Claude (версия в Claude). Прогресс между ними не синхронизируется.
