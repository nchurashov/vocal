# Архитектура «Вокал под бокал»

Документ для всех, кто работает с кодом: как устроено сейчас, какие правила нельзя нарушать и куда движемся.
Решения и тонкости поведения (звук на iPhone, октава голоса, засчёт стен) описаны в `CLAUDE.md` - прочитать до правок.

## Как устроено сейчас

- **Без сервера.** Всё работает в браузере телефона. Данные - в `localStorage` (прогресс) и IndexedDB (видео «до и после»). Наружу ничего не отправляется, пока человек сам не нажмёт «Поделиться».
- **Один HTML.** `build.py` склеивает `src/*.js` и `src/app.css` в `index.html` (сайт на GitHub Pages) и `www/index.html` (iPhone-приложение через Capacitor).
- **Модули по темам (файлы в `src/`):**

| Слой | Файлы | За что отвечает |
| --- | --- | --- |
| Анализ звука | `analysis.js` | Высота тона (YIN), ноты, сравнение с эталоном. Без браузера, тестируется в Node |
| Данные | `data.js` | Упражнения тренажёра, мелодии, базовые ноты |
| Ядро | `app.js` | Звук (Web Audio), микрофон, хранилище и профили, маршруты, экраны тренажёра, настройки |
| Функции | `ball.js`, `game.js`, `warmup.js`, `voice.js`, `range.js`, `diary.js`, `learn.js`, `cam.js` | Игры, распевка, «Голос и речь», замер, «до и после», ноты, камера |

- **Слабые места, которые убираем по плану ниже:**
  1. Файлы склеиваются в один скрипт и общаются через глобальные переменные. Любая функция может случайно перекрыть чужую.
  2. Кнопки привязаны прямо в разметке (`onclick="..."`, около 100 мест), это мешает строгой защите страницы (CSP).
  3. `app.js` слишком большой: ядро и экраны тренажёра вместе.
  4. Версии данных и переносы старых данных разбросаны по модулям (`ballState` v3, профили).

## Правила (обязательны уже сейчас)

1. **Текст от человека** (имя, заметка, всё, что ввели) выводится только через `esc(...)` или `textContent`. Никогда не вставлять его в HTML как есть.
2. **Никаких** `eval`, `new Function`, `document.write`, `setTimeout` со строкой. Внешние скрипты и библиотеки - только по отдельному решению; сейчас разрешены лишь шрифты Google.
3. **Данные человека не уходят с телефона** без явного нажатия. Голос и видео не загружаются никуда.
4. **Микрофон** открывается только через `openMic()`, закрывается через `afterMic()` (правила звука на iPhone - в `CLAUDE.md`).
5. **Новое поле в сохранённых данных** - с версией и переносом старых данных, без потери прогресса человека.
6. **У каждой функции есть тест** в `tests/`. Для игр - тест честности на имитации живого голоса, а не на демо.
7. **Перед выкладкой:** `bash tests/run_all.sh` должен пройти целиком. Это же автоматически делает GitHub Actions (`.github/workflows/tests.yml`) при каждом пуше и pull request.
8. **Тексты:** по-русски, тепло, без канцелярита, без длинного тире (проверяет `tests/check_code.py`).

## Как работать нескольким людям

- Ветка `main` = то, что сейчас на сайте. Прямо в неё не пушим.
- Работа - в отдельной ветке, потом pull request. Автотесты должны быть зелёными, и кто-то второй смотрит изменения.
- В настройках GitHub (Settings → Branches) стоит включить защиту `main`: «Require status checks to pass» (проверка `tests`) и «Require a pull request».
- Изменения в `ios/` и `package.json` после слияния: на Маке `npm i && npx cap sync ios`.

## План по этапам

| Этап | Что делаем | Зачем | Риск |
| --- | --- | --- | --- |
| 1. Правила и проверки | Этот документ, `tests/check_code.py`, `tests/run_all.sh`, автотесты на GitHub | Ничего не ломается незаметно | Нет (сделано) |
| 2. Настоящие модули | Перейти на ES-модули (`import`/`export`) со сборщиком Vite; на выходе тот же один `index.html`. Вместо `onclick="..."` - один обработчик на `data-action`. Разделить `app.js` на `core/audio`, `core/mic`, `core/store`, `core/router`, `core/ui` | Модули не видят чужие переменные, можно включить строгую защиту страницы (CSP) | Средний: меняется всё, страхуют существующие тесты |
| 3. Хранилище | Один модуль `store`: схема данных, номер версии, все переносы старых данных в одном месте, проверка данных при загрузке | Нельзя случайно потерять прогресс | Низкий |
| 4. Типы и стиль | Проверка типов (JSDoc + `tsc --checkJs`, потом TypeScript по частям), ESLint и Prettier в автотестах | Ошибки ловятся до запуска, код одного стиля | Низкий |
| 5. Сервер (когда понадобится) | Вход (Sign in with Apple / Google), синхронизация прогресса между устройствами - отдельным сервисом | Аккаунты, несколько устройств | Высокий: хранение личных данных, согласие людей, закон о персональных данных (для России - 152-ФЗ), расходы на сервер. Решение за Китом |

Целевая структура после этапов 2-3:

```
src/
  core/        audio.js  mic.js  store.js  profiles.js  router.js  ui.js (esc, sheet, toast)
  analysis/    pitch.js  notes.js  evaluate.js
  features/    trainer/  ball/  game/  warmup/  voice/  range/  diary/  learn/  cam/
  data/        exercises.js  melodies.js
tests/         по тесту на каждую функцию + check_code.py + run_all.sh
```

Каждая функция (`features/*`) зависит только от `core` и `analysis`, но не от других функций. Например, камера подключается к игре через небольшой интерфейс (`camSession`, `camRecStart`), а не лезет в её переменные.
